## 二、三个必须知道的工程约束（都已在代码里绕开）

### 1. MapLibre 的球面投影：必须用 v5+，且必须复用它的 shader prelude

`maplibre-gl@4.7.1` **没有 globe 渲染器**——`globe` 只存在于 style spec 的枚举里，`setProjection({type:'globe'})` 会静默失效。真正的球面渲染在 **v5** 才落地，本工程使用 **v5.24**。

更需要注意的是：自定义图层在 globe 模式下拿到的 `u_projection_matrix` 仍然是 **墨卡托矩阵**。直接用它，粒子和球面会完全脱节。

正确做法是复用 MapLibre 通过 `args.shaderData.vertexShaderPrelude` 暴露的官方 prelude：

```glsl
${shaderData.vertexShaderPrelude}
${shaderData.define}          // 定义 GLOBE 宏，缺了它地影裁剪会失效
in vec2 a_pos;
void main() {
  gl_Position = projectTile(a_pos);   // 自动处理 globe/mercator 过渡与地平线裁剪
}
```

坐标约定：prelude 里的 `projectTile` 接受 **归一化 web-mercator [0,1]**，不是 tile 单位的 0..8192。`WindParticleLayer` 的全部几何都以 [0,1] 生成。

prelude 只在 `render()` 期间可用、且随投影变化，因此着色器按 `shaderData.variantName` 惰性编译缓存（`'globe'` / `'mercator'`）。

### 2. Open-Meteo 额度：按「坐标点」计费，且有每日上限

免费层 **每个坐标点算一次调用**，日额度很小；请求 URI 超过约 8 KB 会 414。

因此数据层（`src/data/openMeteo.ts`）：
- 网格固定 **24 × 12 = 288 点**，每 150 点一个请求、共 2 个请求；
- 带 10 分钟内存缓存，切换等压面/变量命中缓存时不消耗额度；
- 本地额度哨兵，超额时立刻在本地失败，而不是烧掉一个 429。

**不要在免费层上做 2592 点全球网格**——实测直接日限流。

### 3. 多模型参数会改字段名

一旦传 `models=ecmwf_ifs025,gfs_seamless,...`，Open-Meteo 会给**每个字段加后缀**：

```
wind_speed_500hPa  →  wind_speed_500hPa_ecmwf_ifs025
```

当初正是这个导致「页面全黑」：查不到键 → 整场 NaN → 纹理全 0 → 图层透明。

现在的处理：默认**不传 `models`**（走 seamless 默认，字段名保持干净），worker 侧另有一层 `_<model>` 后缀兜底（`resolveSeries`）。

### 热力学实现要点

全部公式在 `src/utils/thermodynamics.ts`，已用手算与真实探空交叉验证：

| 量 | 公式 | 验证结果 |
| --- | --- | --- |
| 饱和水汽压 | Bolton (1980) | es(0 °C)=6.112 hPa，es(20 °C)=23.369，es(30 °C)=42.456 ✓ |
| 露点反解 | 上式精确逆 | 往返误差 0（−30…25 °C） ✓ |
| 位温 | θ = T(P0/P)^κ, κ=0.2854 | 往返精确到 1e-15 ✓ |
| LCL | Bolton eq.21（非 Espy） | 比 Espy 更准，接近饱和时不退化 |
| 湿绝热线 | dT/dp = (1/p)(Rd·T+Lv·rs)/(cpd+Lv²rs ε/(RdT²)) | RK2 积分，1000→500 hPa 得 −0.06 °C，符合真实湿绝热 |
| CAPE/CIN | 虚温浮力 + 静力学层厚 | 稳定廓线 CAPE=0；强对流廓线 4129 J/kg；中等 945 J/kg |

**CAPE/CIN 的一个关键细节**：CIN 只累积到 LFC（自由对流高度）为止。早期实现把整层的负浮力都累加，稳定廓线会报出 −14174 J/kg 这种毫无意义的数字。现在若无 LFC，CIN 返回 `NaN`，界面显示「无自由对流」。

| 检查点 | 本地计算 | Open-Meteo 上游 | 结论 |

| 500 hPa 温度 | −13.3 °C | — | 物理合理 |

### 剖面渲染的物理正确性

- **云团**：RH×√(cloud cover) 的门限合成。用逐像素 alpha（离屏 ImageData）而非逐条带填充——后者会让相邻格子的透明度叠加，整片发白。
- **等温线**：Marching Squares，0 °C 实线高亮、−20 °C 虚线。算法已用线性场（精确 x=5.00）、径向场（半径 2.989–3.000）、NaN 孔洞三种用例验证。
- **急流核**：>30 m/s 品红色包络、>45 m/s 加粗发光。实测该剖面最大风速 60 m/s，包络正确落在 150–300 hPa。
- **环流箭头**：水平风沿剖面切向投影 + 垂直速度。ω<0（上升）画绿色向上箭头，ω>0（下沉）画红色向下。

### 三个必须知道的实测发现

**1. RainViewer 超限不返回 404，而是返回"看起来正常"的占位图**

提示词说超过 Zoom 7 会 404。实测并非如此：

| zoom | HTTP | 尺寸 | 颜色类型 | 实际内容 |
| --- | --- | --- | --- | --- |
| z=6, z=7 | 200 | 256×256 | RGBA (type 6) | **真实雷达瓦片** |
| z=8 | 200 | 256×256 | RGB (type 3) | 错误占位图 |
| z=10 | 200 | **512×512** | RGB (type 3) | 错误占位图 |

关键差别是**颜色类型和尺寸**，不是状态码。所以 `maxzoom: 7` 护栏仍然必要——但它防的不是"404 空白"，而是"200 却渲染出灰块/错位图像"这种更难排查的故障。

**2. 传 `models=` 会重写所有字段名**

```
geopotential_height_500hPa  →  geopotential_height_500hPa_ecmwf_ifs025
temperature_2m              →  temperature_2m_ecmwf_ifs025
```

Stage 1 曾被这个坑过一次（整场 NaN）。Stage 3 的所有多模型路径都显式拼接 `_${model.id}` 后缀。

**3. MapLibre 不会为 opacity=0 的 raster 图层加载瓦片**

交叉淡入时若把出站图层设为 `opacity: 0`，MapLibre 认为该图层不可见，**不会请求瓦片并会驱逐已有瓦片**。下次复用该槽位时会出现空白帧。

解决：出站图层降到 `0.004` 而非 `0`——视觉上完全透明，但通过 MapLibre 的可见性判定。

### 热力学/物理验证

**IVT 积分**（`src/utils/ivt.ts`）：

```
IVT = (1/g) · |∫ q·V dp|     对 1000/925/850/700/600/500/400/300 hPa 梯形积分
q = ε·e/(p − 0.378e)         e 由露点经 Bolton 公式推算
```

真实数据交叉验证（2026-11-01 00Z）：

| 位置 | IVT | PWAT | 等级 | 判定 |
| --- | --- | --- | --- | --- |
| 北太平洋 25°N 170°W | **633 kg·m⁻¹·s⁻¹** | 40.1 mm | Cat 2 | 真实水汽输送带 |
| 35°N 150°W | 324 | — | Cat 1 | 边缘 |
| 30°N 140°W | 60 | — | 非 AR | 普通气柱 |

PWAT 40 mm 落在真实 AR 的 30–60 mm 区间，而普通中纬气柱仅 13–20 mm——这个区分度验证了积分算法。

**5880 gpm 线的纬度是真实信号，不是 bug**

实测 ECMWF IFS 在 2026-11-01 00Z 的 500 hPa 高度：

| 纬度 | 高度 |
| --- | --- |
| 0°N | 5868 gpm（低于 5880） |
| **15°N** | **5887 gpm（高于 5880）** |
| 30°N | 5790 gpm |

副高特征线出现在 10–20°N 是**正确的季节特征**：11 月初副高已南退，盛夏才会到 20–30°N。UI 中已按此范围标注提示带。

### 三个必须知道的实测发现

**1. OpenSky 的 CORS 不允许浏览器直连**

提示词未提及这一点。实测响应头是：

```
Access-Control-Allow-Origin: https://opensky-network.org
```

只白名单自家域名。浏览器直连会得到 `TypeError: Failed to fetch` —— **没有任何状态码**，看起来像断网而不是跨域拦截。用 curl 测试时没有 Origin 头，所以完全正常，这正是最容易误判的地方。

解决：OpenSky 请求也走 `/api/awc/opensky/*` 代理，与 AWC 共用同一条链路。vite 代理和 Cloudflare Function 都已支持。

**2. 极光色阶的 60% 阈值在平静期永远不会触发**

提示词写「30-60% 翠绿、>60% 紫红」。实测当前 OVATION 数据（65,160 点）：

| 概率区间 | 格点数 |
| --- | --- |
| 0 | 44,791 |
| 1–4 | 11,862 |
| 5–9 | 4,887 |
| 10–29 | 3,620 |
| **30–59** | **0** |
| **60+** | **0** |

峰值仅 **26%**。固定阈值会让地图永远是一片均匀绿雾，紫红色永不出现。

因此色阶**按当前网格峰值自适应**，图例显示真实概率区间（微弱 3–3%、可见 3–9%、明亮 9–17%、强磁暴 17–23%）。色相仍遵循物理发光色序（绿=氧原子，红/紫=氮分子），只是阈值来自数据。

**3. globe 模式下 `map.getBounds()` 不可靠**

实测在 zoom 1.9 的全球视图下返回：

```
west = -45.7,  east = 255.7,  span = 301.4
```

经度超出 [-180, 180] 且跨度荒谬。拿这个 bbox 去查 METAR/OpenSky，上游返回空或报错。

解决：改为**反投影视口四角**（`map.unproject`），用单位圆平均处理反经线环绕，跨度 >180° 时升级为全球查询。

### 侧风解算验证

公式 `V_cross = |V·sin(Δθ)|`、`V_head = V·cos(Δθ)`，已用已知案例验证：

| 风 | 跑道 | 侧风 | 逆风 | 校验 |
| --- | --- | --- | --- | --- |
| 270°/20kt | 270° | 0 | +20 | ✓ 正逆风 |
| 270°/20kt | 360° | 20 | 0 | ✓ 正侧风 |
| 315°/20kt | 360° | 14.1 | +14.1 | ✓ 45° 分量相等 |
| 360°/20kt | 360° | 0 | −20 | ✓ 顺风 |
| 270°/15G25 | 360° | 15 | 0 | 阵风侧风 25 ✓ |

真实案例（莫斯科 ULMM，METAR `29003MPS`，跑道 090°）：侧风 2.1kt、顺风 −5.6kt，手算一致。

### 关于「三维挤压多边形」

提示词要求「根据 base 至 top 渲染三维半透明挤压多边形」。实测结论：**不做真三维**。

MapLibre 的 `fill-extrusion` 需要以米为单位的高度，且在平面地面上渲染——在 globe 投影下会变成悬浮在球面上方的竖直薄片，严重破坏地理可读性。SIGMET 的垂直范围反而在列表中按 `FL0–FL140` 数值化呈现更准确、更易读。

| 2005 卡特里娜 Katrina | 64 | 150 kt | **902 hPa** | 有 | 42.9 |
| 2024 摩羯 Yagi | 81 | 145 kt | **915 hPa** | 有 | 43.8 |
| 1992 安德鲁 Andrew | 97 | 150 kt | **922 hPa** | **无** | 64.3 |

**与提示词的数值逐项精确匹配**（Tip 870、Patricia 185/872、Haiyan 170/895、Katrina 902、Mangkhut 905、Yagi 915、Meranti 890、Andrew 922）。

**Tip 与 Andrew 没有风圈数据**——1979/1992 年散度计尚未常规归档。界面明确显示「无记录，早于散度计常规归档年代」，而不是画一个看起来合理的假环。

### 两个必须知道的技术发现

**1. ERA5 的 `monthly` 参数会静默失败**

```bash
# 返回空对象（只有元数据，无 monthly 键）
?monthly=temperature_2m_mean
# 返回 31,412 个值
?daily=temperature_2m_mean
```

我最初用 `monthly=` 实现年聚合，接口返回 200 但没有任何数据——这种静默失败比 400 更难发现。已改为 `daily=` 并在本地按年聚合。

**2. 涡旋动画不能做成 Canvas 图层**

Canvas 2D 图层无法跟随 globe 投影（球面曲率会错位）。改用 GeoJSON 点要素逐帧更新位置：每秒推进角度并推入新的 FeatureCollection，300 个粒子的构建成本可以忽略，同时保证涡旋正确贴附在球面上。

### 气候数据验证

上海（31.2°N, 121.5°E）ERA5 逐日聚合结果：

| 指标 | 实测值 |
| --- | --- |
| 数据跨度 | 1940-01-01 至 2025-12-31，**86 个完整年** |
| 基线 1961–1990 | 15.80 °C |
| 首十年（1940s）距平 | +0.55 °C |
| 末十年（2016s）距平 | +1.48 °C |
| **净增温** | **+0.93 °C** |
| 距平范围 | −0.74 .. +3.10 °C |

与上海实际观测（1951–2020 约 1.5–2°C）量级一致。四川盆地（28°N/105°E）算得 +0.43°C，小于沿海——符合内陆盆地的区域差异。

### 关于「七级风圈直径 2220 km」

提示词对泰培的这个说法源自 JTWC 的历史分析，但 **IBTrACS 中没有存储 Tip 的 R34 半径**。因此本项目不显示这个数字，也不据此绘制 2220 km 的风圈——风王竞技场的「R34 风圈」一栏对 Tip 显示「—」。

这是刻意的取舍：编造一个 2220 km 的环很容易，但那样整个比较就失去了可信度。

## 六、已知边界（Stage 1–2 范围）

- L1 海洋、L2 雷达/化学、L4 航空、L5 平流层在 UI 中标注为 `Stage 2+`，仅保留入口与占位。
- 时间轴为逐小时 192 帧（过去 2 天 + 未来 5 天）；额度按 288 点/次计。
- 探针显示的是该等压面的**标准大气近似高度**，非报文层厚。
- 探空与剖面各自消耗 Open-Meteo 坐标额度：1 次探空 = 1 点，1 次剖面 = 20 点。两者与主网格共用同一个分钟预算计数器。
- Skew-T 的湿绝热线是伪绝热近似（不携带凝结物重量），与业务软件的差异在 200 hPa 以上约 1–2 °C。
- 剖面为 15 层（省略 975/950 hPa），因为切片视图中这两层不提供额外信息，且每层都增加请求体积。
- IVT 与面条图各需 162 / 242 个坐标点，与主网格 288 点争抢同一分钟预算。同时开三个面板时需要等待分钟窗口刷新。
- 面条图在独立的墨卡托面板中渲染，不叠加到 3D 球面上——四条细线在球体上会绕过视觉边缘，可读性反而更差。
- 竞技场的混沌窗口阈值取"峰值离散度的 60%"，这是经验值而非气象业务标准；不同变量（如降水通常分歧更大）的可比性有限。
- SIGMET 以平面虚线多边形渲染，三维高度在面板中数值化呈现（见上文说明）。
- 跑道航向使用 12 个基本方位而非真实跑道数据库——AWC 不提供跑道布局，虚构具体跑道号是不诚实的。
- OpenSky 匿名限流约 15 分钟 100 次，因此航班**不自动轮询**，只在切到航班标签页或点刷新时请求。
- 极光色阶按当前峰值自适应，因此同一颜色在磁暴期与平静期代表的概率不同——图例始终显示真实数值以避免误读。
- Tip (1979) 与 Andrew (1992) 在 IBTrACS 中无风圈半径，因此不绘制 R34/R50/R64 环，竞技场中该指标显示「—」。
- 台风轨迹为 6 小时时次的观测/分析最佳路径，不是数值模式输出；两者不可混用。
- 气候条纹的基线固定为 1961–1990（WMO 常用标准），因此显示的距平与该标准直接可比，但与「相对工业化前」的数值不同。
- ERA5 的 `monthly` 参数会返回空数据，必须用 `daily` 并本地聚合。
- 涡旋粒子是示意性动画，不代表实际风场结构；真实风速/气压以面板数值与风圈半径为准。

### Cloudflare Pages 部署

项目使用 Cloudflare Pages + Pages Functions。`functions/api/awc/[[path]].ts`
在边缘代理 AviationWeather.gov 与 OpenSky（两者都禁止浏览器直连），并注入
必需的 `User-Agent` 与边缘缓存。

```bash
npm run build
npx wrangler pages deploy dist --project-name aethersphere-4d
```

配置在 `wrangler.jsonc`：

- `pages_build_output_dir: ./dist` — 静态资源目录
- `compatibility_date: 2026-11-01`
- `compatibility_flags: ["nodejs_compat"]`

首次部署时 Wrangler 会提示创建 Pages 项目。部署后验证两个代理端点：

```bash
curl -I https://<project>.pages.dev/api/awc/isigmet?format=geojson
curl -I "https://<project>.pages.dev/api/awc/opensky/states/all?lamin=30&lomin=-100&lamax=45&lomax=-70"
```

两者都应返回 200 且带 `X-AetherSphere-Cache` 头。
